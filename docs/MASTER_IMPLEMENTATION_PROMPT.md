## 顺序与验收

S0：配置、HTTP、结构化日志、请求 ID、MySQL 连接池、独立可重跑迁移、健康/就绪检查、优雅退出、Compose、CI。验证数据库停机恢复与持久化。

S1：游戏注册、开发身份、可过期和注销的随机令牌、分游戏档案、限流。验证跨玩家/游戏隔离、过期、注销。

S2：Godot 4 SDK、HTTP 超时与有限重试、令牌生命周期、缓存、网络状态、可运行 Demo。以 Godot headless 做解析与集成检查。

S3：槽位、schema_version、revision 乐观锁、删除墓碑、历史恢复、gzip、解压大小限制和 SHA256。验证并发只有一个提交成功，离线冲突保留双方。

S4：游戏事件去重、可信度、JSON 活动规则、时间窗/开放条件、累计/每日/签到/里程碑、版本。验证重复事件和越权。

S5：道具目录、唯一业务键、邮件/附件/过期、事务领取和权威库存。验证并发重试和重启不重复发放。

S6：多榜单/赛季、最高/累计/最低模式、确定性并列排序、附近名次、冻结结算、奖励流水。验证截止与重复结算。

S7：Vue3 + Element Plus GM、管理员鉴权、服务端 RBAC 与游戏授权、玩家/存档/奖励查询、审计。

S8：补发申请、双人审批、撤销、原因/工单、公告、活动草稿/校验/发布/停止/回滚、失败查询。验证幂等与审批边界。

S9：第二款不同玩法游戏只加配置和示例客户端，共用全部后端模块。执行两游戏端到端流程并验证隔离。

S10：PlatformAuth 接口、Steam/TapTap adapter、绑定冲突、安全解绑。没有真实密钥只提供明确的 sandbox adapter；生产拒绝测试凭证，真实平台联调标记未验证。

S11：自然语言→配置、合法枚举与道具查询、JSON Schema 与业务校验、模拟、修复、独立审核、评测。AI 输出视为不可信数据，未经审核不能发布。没有 AI key 用确定性 mock，绝不伪称真实模型效果。

S12：C++20 确定性规则、版本/种子/操作回放、非法操作检测、Protobuf/gRPC、Go 按需调用、超时失败关闭。普通云存档与活动不依赖规则服务。可选 Lua 不列入首版强制范围。

## 约束与交付

采用 Go 模块化单体 + MySQL；不引入无必要的 Redis/Kafka/Kubernetes。每项业务数据都以 game_id 授权和隔离。明确事务边界、幂等键和并发控制，敏感信息不进日志。第一版不做多人 3D 大厅、实时 PvP、通用分发、支付和跨游戏经济。

每阶段记录：改动、命令、真实输出、失败与修复、已知限制和通过/未通过结论。最后运行端到端、并发、重启、数据库故障恢复和适度压测，记录环境与实测数据，不伪造部署或线上性能。输出架构/接口/接入/运行文档、可复现测试、CI，以及所有未验证项。只有验收达标才标记完成；完整实现与测试环境通过不等同于正式上线。
