# MVP 后续补充与验收清单

更新日期：2026-11-06。核对基线：`codex/s0-s12-mvp`，提交 `40aef70`。

当前交付为 Go/MySQL 后端、Godot SDK、GM 网页及 C++ 规则样例组成的本地 sandbox MVP。现有执行记录见 [验收记录](verification/RESULTS.md)；真实渠道、真实 AI、远端 CI 和生产部署需分别验收。本清单是后续工作安排，未勾选项均不表示已经实现或通过验证。

## 1. 推进顺序

| 顺序 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0-A | 可复现的基线与持续集成 | 指定提交在独立环境完成构建、迁移、核心端到端测试，保留命令和结果 |
| P0-B | 会话生命周期修整 | sandbox 与生产会话隔离；注销、过期和撤销后旧令牌均不可访问 |
| P1-A | 一款游戏的真实认证与 SDK 接入 | 真实平台凭证完成登录、档案、存档和重登；伪造凭证失败 |
| P1-B | 正式运营入口与客服操作 | 授权人员完成配置、结算、冻结和解封，越权被拒且操作可追溯 |
| P1-C | 可恢复部署与监控 | 独立数据库恢复演练通过；故障有告警，发布有可执行恢复步骤 |
| P2 | 数据生命周期、后台任务与容量验证 | 清理、任务恢复及目标负载均有量化证据 |

P0 先固定正确性。P1 的运营和恢复工作可在真实渠道凭据准备期间进行。上线前必须完成适用于首款游戏的全部 P0/P1 项；P2 中会影响首发数据量或业务可靠性的项也应提前完成。真实 AI 按产品需求单独验收，不作为普通登录、存档与奖励闭环的前置依赖。

## 2. P0-A：复现与 CI

- [ ] 在独立目录/Compose 项目和新建数据卷中复验，记录提交、工具版本、配置及完整命令；不复用现有 sandbox 数据冒充首次启动。
- [ ] 执行 Go race 测试、vet、构建与格式检查，前端依赖安装/审计/构建，以及 C++ 测试和 Godot SDK/存档测试。
- [ ] 重跑端到端、迁移重复执行/篡改拒绝、生产边界与依赖故障恢复测试，保存对应本次提交的输出。
- [ ] 实际运行 GitHub Actions，修复失败；每项结果关联 workflow run、提交 SHA 和产物。配置文件存在不等于 CI 已通过。
- [ ] CI 失败时保留测试输出、容器状态和经过脱敏的服务日志，并清理本轮测试资源；不删除其他工程数据卷。
- [ ] 给核心流程建立稳定回归入口：玩家登录→存档冲突→活动完成→奖励邮件→并发领取→GM 审批→赛季结算。

验收：另一位开发者按文档在独立环境复现成功；失败记录与最终通过记录可区分；本地、远端 CI、真实平台和生产验收分别报告。

## 3. P0-B：会话与边界正确性

### 已发现的待核验点

基线中 `backend/internal/service/service.go` 的 `actor` 在非 sandbox 环境查询 `hash("production:" + token)`，而 `identity.go` 的 logout 删除 `hash(token)`。本轮已用共同的 `sessionHash` 统一发行、验证和撤销，并通过 SQL 驱动夹具验证注销后失效、其他会话保留与环境隔离；真实 HTTP/MySQL 和真实渠道验收仍待执行。范围见 [客户端接入验证记录](verification/CLIENT_ONLY_INTEGRATION.md)。

- [ ] 复现上述哈希规则不一致，修正后测试同一生产会话注销前可访问、注销后返回 401，同时不能删除其他会话。
- [ ] 将会话发行、查验、撤销的环境规则放在共同入口，避免各路由自行拼接；历史 sandbox 会话在生产中仍然无效。
- [ ] 覆盖令牌过期、非法令牌、重复注销的约定行为、账号冻结后的会话失效，以及玩家令牌/GM 令牌不可互用。
- [ ] 区分“数据库不可用”和“身份无效”的服务端诊断，外部响应不泄漏内部细节；故障日志关联请求 ID。

验收：测试证明实际访问权限失效，不能仅检查 logout 返回 `ok=true`。生产测试使用隔离数据库和明确构造的测试会话，不能通过开放生产游客登录绕过认证边界。

## 4. P1-A：真实认证与游戏接入

- [ ] 按首款游戏发行目标选择一个真实渠道，使用服务端凭据验证真实客户端票据，明确应用与内部账号的映射。
- [ ] 验证伪造、过期、错误应用、重放票据，以及绑定冲突、解绑后账号恢复路径；外部渠道超时有明确失败与重试行为。
- [ ] 约定 SDK 的令牌过期后重登方式，按目标平台实现恢复凭据的安全存储；不将凭据混入普通存档缓存。
- [ ] 固定接口契约、错误码、SDK/API 兼容策略和存档格式升级方式；提供可复制的接入示例。
- [ ] 在一款实际游戏中验证登录、离线进度、两设备冲突、邮件领取和重新登录；保留脱敏记录，区分示例场景与真实游戏。

依赖：真实渠道的开发者资质、应用标识、测试账号及服务端凭据。凭据通过运行环境注入，不写入代码、测试输出或验收文档。

## 5. P1-B：生产运营与客服闭环

- [ ] 提供生产管理员安全初始化、角色/游戏授权、凭据更换和会话撤销流程；开发夹具账号在生产不可用。
- [ ] 为目前 sandbox 限定的游戏注册、榜单配置和赛季结算补齐 GM 入口，服务端校验权限、状态和输入；不能简单移除 sandbox 判断。
- [ ] 配置修改记录操作者、原因、版本和影响范围；有价值的发奖/结算沿用审批及幂等约束，失败后可定位并安全重试。
- [ ] 支持按 UID/名称查询玩家，冻结/解封、强制下线、备注和完整变更历史；明确账号级与游戏级操作范围。
- [ ] 关键列表支持分页、时间范围和查询上限；前端显示成功、失败、等待审批及部分失败的真实状态。
- [ ] 若首款游戏需要区服/多角色，先定义 `server_id`/`role_id` 及权限和迁移方案，再增加字段；不把 `game_id` 当区服使用。

验收：授权客服查到玩家并完成冻结/解封；冻结期间旧会话与重新登录行为符合约定；越权、自审和重复执行测试通过，审计包含结果。

## 6. P1-C：部署、备份与监控

- [ ] 增加独立生产配置，启动时拒绝缺失凭据或开发默认值；明确 TLS、访问入口、数据库权限和 GM 访问范围。
- [ ] 设定可接受的数据损失时间（RPO）和恢复用时（RTO），配置定时备份、保留周期和访问权限。
- [ ] 将真实备份恢复到独立数据库，核验迁移版本、玩家存档、库存和奖励/审批流水；记录实际丢失窗口与恢复耗时，不以重启持久卷替代备份恢复。
- [ ] 明确发布、迁移失败及应用回退流程，演练旧数据升级；破坏性变更先设计兼容与恢复步骤。
- [ ] 采集请求量、错误率、延迟、数据库连接池、慢查询、奖励失败、结算失败和任务积压；通过模拟故障验证告警。
- [ ] 日志可由请求 ID 串联 HTTP、业务失败和关键事务；日志与指标均不携带令牌、密码或无上限的玩家标识标签。

验收：演练结束后有可运行的恢复手册、实测 RPO/RTO 和告警证据；明确值班处理人与故障处置步骤。

## 7. P2：数据、任务与容量

- [ ] 为会话、nonce、事件、回放、审计、存档历史分别规定保留与归档期限；建立合适索引，分批清理并限制每批耗时。
- [ ] 清理前核对防重放与幂等窗口，不能因删除去重记录而再次发奖；奖励账本与审计保留可追溯依据。
- [ ] 当业务需要超过当前每批 100 人时，增加可恢复的群发任务，显示总量、成功、失败、重试和取消状态。
- [ ] 为自动活动和赛季结算设置稳定业务键、任务领取与重启恢复规则；重复触发、多实例争抢和故障恢复均不得重复发奖。
- [ ] 先约定目标玩家数、请求分布、榜单规模与延迟目标，再进行持续负载和故障测试，记录 CPU、内存、连接、锁等待和慢查询。
- [ ] 执行数小时持续运行检查，覆盖成功/失败、断连、重试和大数据集；短时无泄漏记录不能替代长期验证。

## 8. 可维护性与后续功能

- [ ] 将前端、Node 测试和 SQL 整理成可阅读的多行格式，独立提交格式调整；保留已经应用的迁移文件原文与校验和。
- [ ] 逐步为重要输入输出建立具名类型，整理身份、存档、奖励和运营的调用边界；以真实修改成本决定是否拆包。
- [ ] 为新增和修正的关键行为补回归测试，优先越权、并发、事务回滚和故障恢复；不以行数或覆盖率替代行为验证。
- [ ] 按实际游戏需求评估举报工单、关注标签、道具目录、奖励模板和更完整的 GM 榜单管理。
- [ ] 如接入真实 AI，独立验证输出合法性、预算、超时、评测和人工审批；mock 结果不能替代真实模型质量数据。
- [ ] 如提供有价值的竞技奖励，由服务端签发对局上下文并校验使用次数与期限；客户端自选种子及合法回放不能证明真实对局发生。
