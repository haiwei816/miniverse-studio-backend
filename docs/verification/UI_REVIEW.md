# 前端界面体验审核

日期：2026-11-15。只审核，不修改界面代码。对象为当前玩家网页与开发者控制台；既有 Tauri 外壳和原生托盘交互未重新人工检查。

## 实际检查范围

- Cindy 管理的 Chrome 打开隔离实例：玩家 28082、后台 28081，Compose 工程 miniverse-devops-review。
- 玩家桌面截图与 390×844 CSS 像素手机截图、实际布局测量。
- 用仓库公开 sandbox 管理账号登录后台，读取页面、请求状态，实测快捷查玩家；未创建/审批/发布任何业务操作。
- 后台手机布局以实际 DOM 尺寸确认。后台截图两次 CDP 超时，因此不将后台配色和细部视觉作为截图验证结论。
- 辅以两个只读审查检查界面状态与操作链。没有用户测试，不能将推测当成用户行为数据。

## 优先修正

1. **快捷查询丢失 UID（交互复现）。** 从概览打开搜索面板，输入 ui-review-uid，选择查看玩家。跳到玩家页后搜索框为空，并显示全部玩家。`players.js` 初始查询 watcher 没有 immediate；`palette.js` 的快捷补发也只切换运营页，不传入 UID。应保留上下文，把查玩家、查看资产、创建补发连起来。
2. **错误与正常状态混淆（页面及源码确认）。** 登录后游戏列表未完成就挂载概览，实际出现 `/gm/games//overview`、audit、requests 的 404；随后正确游戏请求 200，但页上仍残留 http_404。网页 `/health`、`/ready` 回到 nginx 静态回退页，不能作为 API JSON 健康结果。系统页还把 readiness 失败连带显示成进程离线，失败记录取数失败显示“没有失败记录”。应区分初始化、探测失败、离线、未就绪、真实空数据，提供就地重试。
3. **切游戏与审批操作的上下文保护不足（源码确认）。** 玩家、审计和运营页没有请求代次保护；旧响应可能覆盖新游戏列表。运营加载中旧记录还可操作。切游戏时应取消或忽略旧响应、关闭旧详情、停用旧操作，始终明确正在操作的游戏。
4. **审批缺少面向人的摘要（源码确认）。** 批准会立即执行，名单主要放在原始 JSON 中，审批原因还复用创建表单。建议批准前就地展示游戏、玩家名单/人数、道具、每人数额、总量和独立审批原因，执行时禁用该项操作。
5. **发行草稿丢失风险（源码确认）。** 已有 dirty 检查只阻止提交/发布，切页面会卸载，刷新 tick 会覆盖输入。应增加未保存提醒或按游戏暂存；明确“重新加载”会放弃哪些修改。

## 手机与视觉优化

6. **导航可发现性。** 玩家 ≤600px 导航文字被设为 0px，手机只见四个符号。390px 实测没有页面整体横向溢出，但后台导航自身内容宽744px、可视390px，“审计”和“系统”在首屏外。玩家导航保留短文字；后台用明确菜单或更少的主入口，保留当前游戏名称。
7. **首页优先级。** 玩家390×844视口下，第一组游戏卡片约从 y=910px 开始。大推荐和伙伴推广占满首屏，继续游玩也位于推广之后。建议压缩手机推荐区，把继续玩或游戏入口前移，伙伴推广减少首屏占用。
8. **可读性与点击目标。** 玩家浅色模式浅绿操作文字、浅色错误文字偏淡；后台常用按钮32px，表格按钮26px。对正文强调色与按钮底色分开设计，增大手机触控区域。桌面保留后台紧凑布局。
9. **封面与首图连续性。** 桌面推荐首图下方有明显背景接缝；GameArt仅分卡牌和天空岛两套，未应用发行资料accent/icon。优先修首图尺寸和背景衔接，再让每款游戏有可识别封面。

## 玩家操作细节

- 登录后恢复之前点击的开始玩/收藏，不要求用户重复找入口。
- 游戏库、伙伴资料分别提供加载/错误重试/空状态，读取失败时不要显示可保存的默认资料。
- 聊天在用户位于底部时跟随新消息，回看历史时提示新消息，发送失败保留重试入口。
- 开始聊天前说明规则演示或真实模型模式；用玩家语言替换 basic/context/interactive，显示当前游戏上下文。硬件页目前明确未实现，应保留诚实说明。
- 补齐弹窗焦点进入、限制和恢复，给游戏库封面按钮可访问名称，减少键盘与读屏操作障碍。
- 按角色解释不可用操作；作者看到自己的发布按钮应明确“需要另一位审核人”，避免到提交后才反馈。

## 建议改动顺序及验收

先修快捷操作、错误状态与跨游戏上下文，再改手机导航、首页层级和审批摘要，最后处理对比度、封面、聊天和无障碍细节。

最小复验：390px与桌面下分别完成“登录前点击游戏→登录后继续启动”“搜索UID→资产→创建补发→另一账号核对审批”“修改发行草稿→切页→返回”“模拟读取失败→明确错误→重试”；确认目标游戏与玩家始终一致，未保存内容有恢复机会，错误不会显示成空数据或正常状态。该清单为待验证标准，不代表这些改进已经实现。
