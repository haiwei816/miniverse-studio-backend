# 玩家平台软件版验收

日期：2026-11-14。环境：本机 Windows、Docker Desktop、MySQL 8.4、Node.js 24、Godot 4.7.2。只验证本地隔离环境，没有执行公网发布。

## 运行实例

Compose 项目：`miniverse-load-review`，使用独立数据库卷。

- 玩家平台：`http://127.0.0.1:28082`
- 开发者控制台：`http://127.0.0.1:28081`
- API：`http://127.0.0.1:28080`
- MySQL 健康；迁移 015、016、017 已应用，迁移重复执行成功。

## 通过的自动化检查

- `go test ./...`、`go vet ./...`。
- Linux Go 容器中的 `go test -race ./...`。
- 玩家前端 6 项测试：旧令牌延迟 401、当前令牌失效、匿名认证失败、游戏桥接 JSON/循环/非 JSON 类型/UTF-8 字节限制。
- 玩家前端和开发者前端生产构建；前端依赖安装审计未报告漏洞。
- `tests/player-platform.mjs`：注册登录、目录游标与分类、收藏/最近玩、PKCE 错误校验和单次兑换、跨游戏拒绝、同游戏重启撤权、父会话登出撤权、独立审核发布与下架。
- `tests/companion.mjs`：稳定身份、改名、记忆所有权和删除、未发布世界拒绝、上下文代次、旧票据和旧会话拒绝、登出清空世界、对话历史限制、设备接口预留。
- 现有 `tests/e2e.mjs` 和 `tests/mail-inventory.mjs` 回归。
- Godot `test_sdk.gd`、`test_saves.gd`、新增 `test_platform.gd`；新测试覆盖 PKCE、游戏范围、伙伴 epoch 和游戏会话登出。
- 规则服务构建中的 CTest。

## 浏览器实测

在 Cindy 管理的浏览器中，使用本地测试账号完成：

1. 玩家注册、登录并启动天空岛。
2. 收集木材、升级建筑，观察自动云存档成功。
3. 返回平台后重新进入，云端读取并恢复建筑等级。
4. 启动卡牌示例，翻牌配对，观察进度保存。
5. 游戏内伙伴接收当前场景并返回明确标记的规则演示建议。
6. 伙伴改名、保存设置、明确保存一条记忆、文字对话。
7. 开发者控制台登录，打开游戏发行资料表；发布权限另外由 API 集成测试覆盖。
8. 桌面及 390px 手机视口的页面检查；未发现横向溢出。

## 尚未验证或实现

- 没有配置真实模型凭证，因此真实外部模型仅以本地 HTTP stub 验证请求/响应和错误边界；实际质量、费用与网络延迟未验收。Sandbox 页面明确使用演示回复。
- 嵌入式仅有协议 schema、能力查询、软件快照；真实配对返回 501。没有设备绑定、音频传输或固件实现。
- 当前交付网页游戏平台及网页接入示例，未实现原生 Windows/APK 安装发行、开发者自助组织入驻、支付或社区。
- 没有对新平台和 AI 服务测量生产容量，旧档案读取 QPS 不适用于这些新功能。
